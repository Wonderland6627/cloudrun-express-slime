# 503错误排查与解决方案

## 🔍 问题描述

服务部署在微信云托管中，访问时出现503错误，过一会才恢复正常。

## 📋 可能原因分析

### 1. 服务冷启动问题（最可能）⭐

**原因**：
- 云托管服务配置了 `MinNum=0`（最小实例数为0）
- 当没有请求时，服务会自动缩容到0，节省成本
- 首次访问需要启动新实例，启动过程需要时间（通常5-30秒）
- 在实例完全启动前，请求会返回503错误

**特征**：
- ✅ 首次访问返回503
- ✅ 等待几秒后再次访问恢复正常
- ✅ 一段时间不访问后，再次访问又出现503

**解决方案**：
1. 登录 [腾讯云托管控制台](https://console.cloud.tencent.com/tcb/cloudrun)
2. 进入服务详情页 → **"配置"** 或 **"版本管理"** → 选择当前版本
3. 找到 **"扩缩容配置"** 或 **"实例配置"**
4. 将 **"最小实例数"**（MinNum）从 `0` 修改为 `1`
5. 保存配置并重新部署

**优缺点**：
- ✅ 优点：消除冷启动延迟，提升用户体验
- ⚠️ 缺点：会产生持续运行费用（即使没有请求）

### 2. 健康检查超时

**原因**：
- 服务启动时间较长（依赖安装、数据库连接等）
- 健康检查在服务完全启动前就超时
- 云托管认为服务不健康，返回503

**解决方案**：
1. 检查服务启动日志，确认启动时间
2. 优化启动流程，减少启动时间：
   - 使用更轻量的基础镜像
   - 优化依赖安装（使用缓存）
   - 延迟初始化非关键组件
3. 在云托管控制台调整健康检查超时时间（如果支持）

### 3. 端口配置不一致

**原因**：
- Dockerfile中设置了 `ENV PORT=80`
- 但云托管控制台配置的端口可能不一致
- 导致健康检查失败

**解决方案**：
1. 确认 Dockerfile 中设置了 `ENV PORT=80`
2. 在云托管控制台，确认端口配置为 `80`（或留空使用默认值）
3. 检查 `bin/www` 是否正确读取 `process.env.PORT`

### 4. 资源不足

**原因**：
- CPU/内存配置过低
- 服务启动缓慢或失败

**解决方案**：
1. 检查服务日志，查看是否有资源相关错误
2. 适当增加CPU/内存配置：
   - 最小配置：CPU 0.25核，内存 0.5GB
   - 推荐配置：CPU 0.5核，内存 1GB

## 🔧 推荐配置

### 云托管服务配置建议

```yaml
# 实例配置
MinNum: 1          # 最小实例数，建议设置为1避免冷启动
MaxNum: 10         # 最大实例数，根据业务需求调整

# 资源配置
CPU: 0.5           # CPU核数
Memory: 1          # 内存GB（必须是CPU的2倍）

# 端口配置
Port: 80           # 服务端口（与Dockerfile中的PORT一致）

# 扩缩容策略
PolicyType: cpu    # 基于CPU使用率扩缩容
PolicyThreshold: 60 # 当CPU使用率达到60%时触发扩缩容
```

### 健康检查优化

已添加 `/health` 健康检查端点，返回简单的JSON响应，便于云托管进行健康检查。

## 📝 检查清单

在排查503错误时，请按以下顺序检查：

- [ ] **1. 检查最小实例数配置**
  - 登录云托管控制台
  - 查看服务配置中的 `MinNum` 值
  - 如果为0，建议改为1

- [ ] **2. 查看服务日志**
  - 在云托管控制台查看服务日志
  - 检查是否有启动错误
  - 查看服务启动时间

- [ ] **3. 验证端口配置**
  - 确认 Dockerfile 中 `ENV PORT=80`
  - 确认云托管控制台端口配置为 `80`
  - 确认 `bin/www` 正确读取环境变量

- [ ] **4. 测试健康检查端点**
  ```bash
  curl https://your-service-domain/health
  ```
  应该返回：`{"status":"ok"}`

- [ ] **5. 检查资源使用情况**
  - 查看CPU/内存使用率
  - 如果持续高使用率，考虑增加资源配置

## 🚀 快速解决方案

**如果问题确实是冷启动导致的，最快的解决方案是：**

1. 登录 [腾讯云托管控制台](https://console.cloud.tencent.com/tcb/cloudrun)
2. 进入服务详情 → **"配置"** → **"版本管理"**
3. 选择当前运行版本 → **"编辑配置"**
4. 找到 **"最小实例数"**，将值从 `0` 改为 `1`
5. 保存并重新部署

**注意**：修改配置后需要重新部署才能生效。
